## 1. 엔티티 검증 규칙

### Store
| 규칙 ID | 규칙 | 검증 시점 |
|---------|------|-----------|
| BR-S01 | storeCode는 비어있을 수 없음 (1~50자) | 생성 시 |
| BR-S02 | storeCode는 시스템 전체에서 고유해야 함 | 생성 시 |
| BR-S03 | storeName은 비어있을 수 없음 (1~100자) | 생성/수정 시 |

### Admin
| 규칙 ID | 규칙 | 검증 시점 |
|---------|------|-----------|
| BR-A01 | username은 비어있을 수 없음 (1~50자) | 생성 시 |
| BR-A02 | 동일 매장 내 username은 고유해야 함 | 생성 시 |
| BR-A03 | password는 최소 8자 이상 | 생성/변경 시 |
| BR-A04 | role은 OWNER, MANAGER, STAFF 중 하나 | 생성/변경 시 |
| BR-A05 | password는 bcrypt로 해싱하여 저장 | 생성/변경 시 |

### StoreTable
| 규칙 ID | 규칙 | 검증 시점 |
|---------|------|-----------|
| BR-T01 | tableNumber는 1 이상의 정수 | 생성 시 |
| BR-T02 | 동일 매장 내 tableNumber는 고유해야 함 | 생성 시 |
| BR-T03 | password는 최소 4자 이상 | 생성/변경 시 |
| BR-T04 | password는 bcrypt로 해싱하여 저장 | 생성/변경 시 |

### Category
| 규칙 ID | 규칙 | 검증 시점 |
|---------|------|-----------|
| BR-CT01 | name은 비어있을 수 없음 (1~50자) | 생성/수정 시 |
| BR-CT02 | 동일 매장 내 카테고리명은 고유해야 함 | 생성/수정 시 |
| BR-CT03 | displayOrder는 0 이상의 정수 | 생성/수정 시 |

### Menu
| 규칙 ID | 규칙 | 검증 시점 |
|---------|------|-----------|
| BR-M01 | name은 비어있을 수 없음 (1~100자) | 생성/수정 시 |
| BR-M02 | price는 0 이상의 정수 (원 단위) | 생성/수정 시 |
| BR-M03 | price는 10,000,000원 이하 | 생성/수정 시 |
| BR-M04 | categoryId는 유효한 카테고리를 참조해야 함 | 생성/수정 시 |
| BR-M05 | description은 최대 500자 | 생성/수정 시 |
| BR-M06 | displayOrder는 0 이상의 정수 | 생성/수정 시 |

### Order
| 규칙 ID | 규칙 | 검증 시점 |
|---------|------|-----------|
| BR-O01 | 주문에는 최소 1개 이상의 OrderItem이 포함되어야 함 | 생성 시 |
| BR-O02 | totalAmount는 모든 OrderItem의 (unitPrice * quantity) 합과 일치해야 함 | 생성 시 |
| BR-O03 | orderNumber는 시스템 전체에서 고유해야 함 | 생성 시 |
| BR-O04 | 주문 생성 시 status는 PENDING으로 설정 | 생성 시 |

### OrderItem
| 규칙 ID | 규칙 | 검증 시점 |
|---------|------|-----------|
| BR-OI01 | quantity는 1 이상의 정수 | 생성 시 |
| BR-OI02 | menuId는 유효한 메뉴를 참조해야 함 | 생성 시 |
| BR-OI03 | menuName과 unitPrice는 주문 시점의 메뉴 정보 스냅샷 | 생성 시 |

## 2. 보안 규칙

### 인증 규칙
| 규칙 ID | 규칙 | 설명 |
|---------|------|------|
| SEC-01 | 관리자 JWT 토큰 유효 기간: 16시간 | 16시간 후 자동 만료 |
| SEC-02 | 테이블 JWT 토큰 유효 기간: 16시간 | 태블릿 세션 유지 |
| SEC-03 | JWT에 역할(role) 정보 포함 | 관리자 토큰에 AdminRole 포함 |
| SEC-04 | JWT에 매장 ID(storeId) 포함 | 매장 격리를 위한 필수 정보 |
| SEC-05 | 로그인 실패 5회 시 계정 30분 잠금 | brute-force 방지 |
| SEC-06 | 잠금 해제 후 loginAttempts 초기화 | 잠금 시간 경과 후 자동 해제 |

### 권한 규칙 (RBAC)
| 규칙 ID | 기능 | OWNER | MANAGER | STAFF |
|---------|------|-------|---------|-------|
| RBAC-01 | 실시간 주문 모니터링 | ✅ | ✅ | ✅ |
| RBAC-02 | 주문 상태 변경 | ✅ | ✅ | ✅ |
| RBAC-03 | 주문 삭제 | ✅ | ✅ | ❌ |
| RBAC-04 | 테이블 초기 설정 | ✅ | ✅ | ❌ |
| RBAC-05 | 테이블 이용 완료 | ✅ | ✅ | ❌ |
| RBAC-06 | 과거 주문 내역 조회 | ✅ | ✅ | ❌ |
| RBAC-07 | 메뉴 등록/수정/삭제 | ✅ | ✅ | ❌ |
| RBAC-08 | 메뉴 노출 순서 조정 | ✅ | ✅ | ❌ |
| RBAC-09 | 관리자 계정 관리 | ✅ | ❌ | ❌ |

### 매장 격리 규칙
| 규칙 ID | 규칙 | 설명 |
|---------|------|------|
| ISO-01 | 모든 데이터 접근은 storeId로 필터링 | 다른 매장 데이터 접근 불가 |
| ISO-02 | JWT의 storeId와 요청 데이터의 storeId 일치 검증 | 매장 간 데이터 격리 보장 |
| ISO-03 | SSE 스트림은 매장별로 분리 | 다른 매장의 주문 이벤트 수신 불가 |

## 3. 공통 비즈니스 규칙

### 에러 처리 규칙
| 규칙 ID | 규칙 | 설명 |
|---------|------|------|
| ERR-01 | 모든 API 에러 응답은 통일된 형식 사용 | {error, message, timestamp, path} |
| ERR-02 | 프로덕션 환경에서 스택 트레이스 노출 금지 | 일반적인 에러 메시지만 반환 |
| ERR-03 | 404 Not Found: 리소스 미존재 시 | 엔티티 조회 실패 |
| ERR-04 | 400 Bad Request: 입력 검증 실패 시 | 필수 필드 누락, 형식 오류 |
| ERR-05 | 401 Unauthorized: 인증 실패 시 | 토큰 없음, 만료, 유효하지 않음 |
| ERR-06 | 403 Forbidden: 권한 부족 시 | RBAC 위반 |
| ERR-07 | 409 Conflict: 중복 데이터 시 | UNIQUE 제약 위반 |

### 타임스탬프 규칙
| 규칙 ID | 규칙 | 설명 |
|---------|------|------|
| TS-01 | 모든 시각은 UTC 기준 저장 | DB에 UTC로 저장 |
| TS-02 | createdAt은 엔티티 생성 시 자동 설정 | @PrePersist |
| TS-03 | updatedAt은 엔티티 수정 시 자동 갱신 | @PreUpdate |

### 주문 번호 생성 규칙
| 규칙 ID | 규칙 | 설명 |
|---------|------|------|
| ON-01 | 형식: yyyyMMdd-HHmmss-XXXX (X=랜덤 4자리) | 날짜+시간+랜덤 조합 |
| ON-02 | 시스템 전체에서 고유해야 함 | UNIQUE 제약 |
