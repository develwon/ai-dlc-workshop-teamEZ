## 1. 주문 상태 전이 모델

### 상태 전이 다이어그램
```
+----------+     상태 변경      +-----------+     상태 변경      +-----------+
| PENDING  | ----------------> | PREPARING | ----------------> | COMPLETED |
| (대기중)  |                   | (준비중)   |                   | (완료)     |
+----------+                   +-----------+                   +-----------+
```

### 전이 규칙
| 현재 상태 | 허용 전이 | 설명 |
|-----------|-----------|------|
| PENDING | → PREPARING | 주문 접수 후 준비 시작 |
| PENDING | → COMPLETED | 즉시 완료 처리 (빠른 메뉴) |
| PREPARING | → COMPLETED | 준비 완료 |
| COMPLETED | (전이 불가) | 최종 상태 |

### 전이 제약
- 역방향 전이 불가 (COMPLETED → PREPARING, PREPARING → PENDING)
- 삭제된 주문은 상태 전이 불가
- 상태 변경 시 updatedAt 자동 갱신

## 2. 테이블 세션 라이프사이클

### 세션 상태 흐름
```
[테이블 비활성]
      |
      | 첫 주문 생성 시 자동 세션 시작
      v
+------------------+
| ACTIVE SESSION   |
| (endTime = NULL) |
+------------------+
      |
      | 추가 주문 가능 (동일 세션)
      |
      | 관리자 "이용 완료" 처리
      v
+------------------+
| CLOSED SESSION   |
| (endTime = NOW)  |
+------------------+
      |
      | 주문 이력 아카이빙
      | 테이블 주문 목록 리셋
      v
[테이블 비활성]
      |
      | 새 고객 첫 주문 시 새 세션 시작
      v
+------------------+
| NEW SESSION      |
| (endTime = NULL) |
+------------------+
```

### 세션 규칙
| 규칙 ID | 규칙 | 설명 |
|---------|------|------|
| SES-01 | 테이블당 활성 세션은 최대 1개 | endTime IS NULL인 세션이 1개만 존재 |
| SES-02 | 세션은 첫 주문 생성 시 자동 시작 | 활성 세션이 없으면 새 세션 생성 |
| SES-03 | 세션 종료는 관리자만 가능 (이용 완료) | OWNER, MANAGER 역할만 |
| SES-04 | 세션 종료 시 모든 주문을 OrderHistory로 이동 | 아카이빙 처리 |
| SES-05 | 세션 종료 후 새 주문 시 새 세션 자동 시작 | 이전 세션과 독립 |
| SES-06 | 고객은 현재 활성 세션의 주문만 조회 가능 | 이전 세션 주문 제외 |

## 3. SSE (Server-Sent Events) 이벤트 모델

### 이벤트 유형
| 이벤트 | 발생 시점 | 데이터 |
|--------|-----------|--------|
| ORDER_CREATED | 새 주문 생성 시 | 주문 정보 (주문번호, 테이블, 메뉴, 금액) |
| ORDER_STATUS_CHANGED | 주문 상태 변경 시 | 주문 ID, 이전 상태, 새 상태 |
| ORDER_DELETED | 주문 삭제 시 | 주문 ID, 테이블 ID |
| TABLE_COMPLETED | 테이블 이용 완료 시 | 테이블 ID |

### SSE 관리 규칙
| 규칙 ID | 규칙 | 설명 |
|---------|------|------|
| SSE-01 | SSE 연결은 매장별로 관리 | storeId 기준 emitter 그룹화 |
| SSE-02 | 연결 타임아웃: 30분 | 30분 후 자동 재연결 필요 |
| SSE-03 | 연결 실패 시 자동 제거 | 에러 발생 emitter 정리 |
| SSE-04 | 이벤트 전달 지연: 2초 이내 | 성능 요구사항 |

## 4. 에러 응답 모델

### 통일된 에러 응답 형식
```json
{
  "error": "ERROR_CODE",
  "message": "사용자 친화적 에러 메시지",
  "timestamp": "2026-04-30T09:00:00Z",
  "path": "/api/orders"
}
```

### 에러 코드 체계
| 에러 코드 | HTTP 상태 | 설명 |
|-----------|-----------|------|
| VALIDATION_ERROR | 400 | 입력 검증 실패 |
| UNAUTHORIZED | 401 | 인증 실패 |
| FORBIDDEN | 403 | 권한 부족 |
| NOT_FOUND | 404 | 리소스 미존재 |
| CONFLICT | 409 | 중복 데이터 |
| INVALID_STATE_TRANSITION | 400 | 잘못된 상태 전이 |
| ACCOUNT_LOCKED | 423 | 계정 잠금 |
| INTERNAL_ERROR | 500 | 서버 내부 오류 |
