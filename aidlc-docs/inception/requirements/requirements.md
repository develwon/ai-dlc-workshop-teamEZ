## 1. 기술 스택 결정사항

| 영역 | 기술 | 비고 |
|------|------|------|
| **백엔드** | Java + Spring Boot | 당사 프레임워크 환경 |
| **프론트엔드** | HTML + JavaScript + CSS (바닐라) | 프레임워크 미사용 |
| **데이터베이스** | PostgreSQL | 관계형 DB |
| **실시간 통신** | Server-Sent Events (SSE) | 관리자 주문 모니터링용 |
| **인증** | JWT 토큰 기반 | 16시간 세션 |
| **이미지 저장소** | 클라우드 스토리지 (AWS S3 등) | 메뉴 이미지 업로드 |
| **프로젝트 구조** | 모노레포 | 프론트엔드 + 백엔드 단일 저장소 |
| **배포 환경** | 클라우드 (AWS, GCP, Azure 등) | 추후 구체화 |

## 2. 비즈니스 컨텍스트

### 2.1 서비스 비전
디지털 주문 시스템을 통해 고객에게는 편리한 주문 경험을, 매장 운영자에게는 효율적인 운영 환경을 제공하는 차세대 테이블오더 플랫폼

### 2.2 핵심 가치 제안
- **고객**: 대기 시간 없는 즉시 주문, 직관적 인터페이스
- **매장 운영자**: 인건비 절감, 실시간 주문 관리/모니터링
- **시장 차별화**: 다양한 업종 적용 가능, 직관적 관리자 도구

### 2.3 운영 규모
- **매장 관리**: 다중 매장 지원 (각 매장 독립 운영)
- **매장당 테이블**: 중규모 11~30개
- **동시 주문 처리량**: 피크 시간 기준 분당 10~50건
- **관리자 계정**: 매장당 다수 계정, 역할 기반 (매장주, 매니저, 직원 등)

## 3. 기능 요구사항 (Functional Requirements)

### 3.1 고객용 기능 (Customer Features)

#### FR-C01: 테이블 태블릿 자동 로그인 및 세션 관리
- **목적**: 고객이 별도 로그인 절차 없이 즉시 주문
- **초기 설정 (관리자 1회 수행)**:
  - 매장 식별자 입력
  - 테이블 번호 입력
  - 테이블 비밀번호 입력
  - 로그인 정보 로컬 저장
- **자동 로그인**: 1회 로그인 성공 후 저장된 정보로 자동 로그인
- **세션 관리**: 테이블 세션은 첫 주문 시작부터 이용 완료 처리까지

#### FR-C02: 메뉴 조회 및 탐색
- **목적**: 매장 메뉴를 쉽게 탐색하고 선택
- **기본 화면**: 메뉴 화면이 기본 화면으로 항상 표시
- 카테고리별 메뉴 분류 및 표시
- 메뉴 상세 정보: 메뉴명, 가격, 설명, 이미지
- 카테고리 간 빠른 이동
- **UI/UX**: 카드 형태 레이아웃, 터치 친화적 버튼 (최소 44x44px), 명확한 시각적 계층 구조

#### FR-C03: 장바구니 관리
- **목적**: 주문 전 선택 메뉴 임시 저장 및 수정
- 메뉴 추가/삭제
- 수량 조절 (증가/감소)
- 총 금액 실시간 계산
- 장바구니 비우기
- **데이터 관리**: 클라이언트 측 임시 저장 (페이지 새로고침 시에도 유지, localStorage 활용)
- 서버 전송은 주문 확정 시에만 수행

#### FR-C04: 주문 생성
- **목적**: 장바구니 메뉴를 실제 주문으로 전환
- 주문 내역 최종 확인
- 주문 확정 버튼
- **주문 성공 플로우**: 주문 번호 표시 → 장바구니 자동 비우기 → 5초 후 메뉴 화면 자동 리다이렉트
- **주문 실패**: 에러 메시지 표시, 장바구니 유지
- **주문 정보**: 매장 식별 정보, 테이블 식별 정보, 주문 메뉴 목록 (메뉴명, 수량, 단가), 총 주문 금액, 세션 ID

#### FR-C05: 주문 내역 조회
- **목적**: 현재 테이블의 주문 이력 확인
- 주문 시간 순 정렬
- 주문별 상세: 주문 번호, 주문 시각, 주문 메뉴/수량, 주문 금액, 주문 상태 (대기중/준비중/완료)
- **데이터 필터링**: 현재 테이블 세션 주문만 표시, 이용 완료 처리된 주문 제외
- 페이지네이션 또는 무한 스크롤

### 3.2 관리자용 기능 (Admin Features)

#### FR-A01: 매장 인증
- **목적**: 관리자가 매장 관리 시스템에 접근
- 매장 식별자 + 사용자명 + 비밀번호 입력
- **세션 관리**: 16시간 세션 유지, JWT 토큰 기반, 브라우저 새로고침 시 유지, 16시간 후 자동 로그아웃
- **보안**: bcrypt 해싱, 로그인 시도 제한
- **역할 기반 접근 제어**: 매장주, 매니저, 직원 등 역할 구분

#### FR-A02: 실시간 주문 모니터링
- **목적**: 들어오는 주문을 실시간으로 확인/관리
- **SSE 기반 실시간 업데이트** (2초 이내 주문 표시)
- **그리드/대시보드 레이아웃**: 테이블별 카드 형태, 각 카드에 총 주문액 표시, 최신 주문 n개 미리보기
- 주문별 상세: 테이블 번호, 주문 번호, 주문 시각, 주문 메뉴/수량 (축약), 총 금액
- **주문 카드 클릭 시**: 전체 메뉴 목록 상세 보기
- 주문 상태 변경 (대기중/준비중/완료)
- 신규 주문 시각적 강조 (색상 변경, 애니메이션)
- 테이블별 필터링 기능

#### FR-A03: 테이블 관리
- **테이블 태블릿 초기 설정**: 테이블 번호/비밀번호 설정, 16시간 세션 생성
- **주문 삭제 (직권 수정)**: 특정 주문 삭제, 확인 팝업, 테이블 총 주문액 재계산
- **테이블 세션 처리**:
  - 세션 시작 (첫 주문) 및 종료 (이용 완료) 관리
  - 이용 완료 시: 주문 내역을 과거 이력으로 이동, 현재 주문 목록/총 주문액 0으로 리셋
  - 새 고객이 이전 주문 내역 없이 시작 가능
- **과거 주문 내역 조회**: 테이블별 과거 주문 목록 (시간 역순), 날짜 필터링

#### FR-A04: 메뉴 관리 (MVP 포함)
- **목적**: 메뉴 정보를 동적으로 관리
- 메뉴 조회 (카테고리별)
- 메뉴 등록: 메뉴명, 가격, 설명, 카테고리, 이미지 (S3 업로드)
- 메뉴 수정
- 메뉴 삭제
- 메뉴 노출 순서 조정
- **데이터 검증**: 필수 필드 검증, 가격 범위 검증

## 4. 비기능 요구사항 (Non-Functional Requirements)

### NFR-01: 성능
- 주문 생성 API 응답 시간: 500ms 이내
- 메뉴 조회 API 응답 시간: 300ms 이내
- SSE 주문 알림 지연: 2초 이내
- 동시 주문 처리: 분당 10~50건 (피크 시간)
- 매장당 테이블: 최대 30개

### NFR-02: 보안
- JWT 토큰 기반 인증 (관리자 16시간, 테이블 세션 기반)
- 비밀번호 bcrypt 해싱
- 로그인 시도 제한 (brute-force 방지)
- 역할 기반 접근 제어 (RBAC)
- HTTPS 필수 (TLS 1.2+)
- HTTP 보안 헤더 적용
- 입력 값 검증 및 SQL Injection 방지
- CORS 정책 적용
- SECURITY 확장 규칙 전체 적용 (SECURITY-01 ~ SECURITY-15)

### NFR-03: 가용성
- 서비스 가용성: 99.5% 이상
- 장애 시 graceful degradation

### NFR-04: 확장성
- 다중 매장 지원 (매장 간 데이터 격리)
- 수평 확장 가능한 아키텍처

### NFR-05: 사용성
- 터치 친화적 UI (최소 44x44px 터치 타겟)
- 직관적인 네비게이션
- 반응형 디자인 (태블릿 최적화)
- 접근성 준수 (WCAG 기본 수준)

### NFR-06: 유지보수성
- 계층형 아키텍처 (Controller - Service - Repository)
- 코드 문서화
- 단위 테스트 커버리지

## 5. 제외 기능 (Out of Scope)

다음 기능은 이번 MVP에서 구현하지 않습니다:

- **결제**: 실제 결제 처리, PG사 연동, 영수증, 환불, 포인트/쿠폰
- **인증**: OAuth, SNS 로그인, 2FA/OTP
- **파일 관리**: 이미지 리사이징/최적화, CMS, 광고
- **알림**: 푸시 알림, SMS, 이메일, 소리/진동
- **주방**: 주방 전달, 재고 관리
- **고급 기능**: 데이터 분석, 매출 리포트, 재고 관리, 직원 관리, 예약, 리뷰, 다국어
- **외부 연동**: 배달 플랫폼, POS, 소셜 미디어, 지도 API, 번역 API

## 6. 데이터 모델 개요

### 핵심 엔티티
- **Store**: 매장 정보 (매장 식별자, 매장명, 주소 등)
- **Admin**: 관리자 계정 (사용자명, 비밀번호 해시, 역할, 소속 매장)
- **Table**: 테이블 정보 (테이블 번호, 비밀번호, 소속 매장)
- **TableSession**: 테이블 세션 (세션 ID, 테이블, 시작 시각, 종료 시각)
- **Category**: 메뉴 카테고리 (카테고리명, 노출 순서, 소속 매장)
- **Menu**: 메뉴 항목 (메뉴명, 가격, 설명, 이미지 URL, 카테고리, 노출 순서)
- **Order**: 주문 (주문 번호, 테이블 세션, 주문 시각, 총 금액, 상태)
- **OrderItem**: 주문 항목 (주문, 메뉴, 수량, 단가)
- **OrderHistory**: 과거 주문 이력 (이용 완료 시 이동)

## 7. API 개요

### 고객용 API
| Method | Endpoint | 설명 |
|--------|----------|------|
| POST | /api/tables/login | 테이블 태블릿 로그인 |
| GET | /api/stores/{storeId}/menus | 메뉴 목록 조회 |
| GET | /api/stores/{storeId}/categories | 카테고리 목록 조회 |
| POST | /api/orders | 주문 생성 |
| GET | /api/tables/{tableId}/orders | 현재 세션 주문 내역 조회 |

### 관리자용 API
| Method | Endpoint | 설명 |
|--------|----------|------|
| POST | /api/admin/login | 관리자 로그인 |
| GET | /api/admin/orders/stream | SSE 실시간 주문 스트림 |
| GET | /api/admin/orders | 주문 목록 조회 |
| PATCH | /api/admin/orders/{orderId}/status | 주문 상태 변경 |
| DELETE | /api/admin/orders/{orderId} | 주문 삭제 |
| POST | /api/admin/tables/{tableId}/complete | 테이블 이용 완료 |
| GET | /api/admin/tables/{tableId}/history | 과거 주문 내역 조회 |
| POST | /api/admin/tables | 테이블 초기 설정 |
| GET | /api/admin/menus | 메뉴 목록 조회 |
| POST | /api/admin/menus | 메뉴 등록 |
| PUT | /api/admin/menus/{menuId} | 메뉴 수정 |
| DELETE | /api/admin/menus/{menuId} | 메뉴 삭제 |
| PATCH | /api/admin/menus/order | 메뉴 노출 순서 변경 |

## 8. 용어 정의

| 용어 | 정의 |
|------|------|
| **MVP** | Minimum Viable Product (최소 기능 제품) |
| **테이블 세션** | 특정 테이블에 고객이 앉아서 첫 주문 시작 후부터 이용 완료 처리까지의 시간 |
| **SSE** | Server-Sent Events (서버에서 클라이언트로의 단방향 실시간 통신) |
| **JWT** | JSON Web Token (인증 토큰) |
| **RBAC** | Role-Based Access Control (역할 기반 접근 제어) |
| **bcrypt** | 비밀번호 해싱 알고리즘 |
